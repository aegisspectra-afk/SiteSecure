## 0. לקרוא בשלושה משפטים

SITE SECURE היא **מערכת הפעלה לחברות התקנת אבטחה** (מצלמות, אזעקה, בקרת כניסה, רשת).  
היא רצה בעברית, מימין לשמאל, כ־SPA תחת `https://…/site-secure/`, מעל אותו חשבון Supabase כמו אתר Aegis.  
המשתמש נכנס דרך Aegis (התחברות), ואז עובד בתוך SITE SECURE: ליד → הצעת מחיר → פרויקט → תיק אתר → שטח → אחריות.

## 1. מה המוצר פותר

הכאב שהלנדינג מגדיר במפורש (`landingContent.ts`):

- תמונות וכתובות מתפזרות ב־WhatsApp
- הצעות ומחירים באקסל בכפילות
- קבצים ב־Drive שאי אפשר למצוא
- שעתיים ביום על תיאומים בטלפון

ההבטחה: **תיק אתר חי** לכל התקנה — לקוח, ציוד, מסמכים, אחריות, שירות — במקום אחד.

קהל: מתקיני אבטחה, טכנאי מתח נמוך, חברות CCTV/אזעקה, אינטגרטורים.

## 4. המסע מהכניסה עד העבודה

### 4.1 אורח — דף נחיתה `/site-secure/`

עמוד שיווק מלא בעברית, RTL, בלי AppShell.

**מבנה (מלמעלה למטה):**

1. Header דביק עם לוגו Aegis + תווית SITE SECURE, עוגנים (הכאב, ROI, תיק אתר, Digital Twin, אמון, פיילוט), כפתורי התחברות/הרשמה ל־Aegis
2. Hero — «סוף לרדוף אחרי העסק» + CTA «הצטרפו לפיילוט»
3. כאב → ROI כסף → תיק אתר → Digital Twin → פלטפורמה → workflow → שטח מובייל → מסכי מוצר → תמחור → FAQ → CTA → פוטר

אם המשתמש כבר מחובר: הכפתור הופך ל־**לדשבורד** (או **יצירת סביבה** אם אין workspace).

### 4.2 זהות בלי חברה — Onboarding

מי שהתחבר ב־Aegis ואין לו שורת `company_members` מגיע ל־`/onboarding` (לא נוצרת סביבה בשקט).

הטופס:

- בחירת תוכנית: Solo / Business / Enterprise
- שם חברה, מדינה, שפה, אזור זמן, מטבע, סוג עסק, גודל
- נשמר ב־`sessionStorage` תחת `ss_pending_workspace`

אחר כך:

| תוכנית | לאן |
|--------|-----|
| Solo | `/provisioning` — אנימציה קולנועית (גריד + זוהר כחול) → RPC יוצר חברה → דשבורד |
| Business | `/checkout` → Stripe (או Demo) → `/checkout/success` → יצירת סביבה |
| Enterprise | בקשה נרשמת כליד אתר + טלגרם. אין workspace מיד |

אחרי יצירה: מודל **ברוכים הבאים לסביבה**.

### 4.3 הזמנת עובד / Founding Technician

בעלים → הגדרות → משתמשים · Founding Tech → הזמנה במייל (חובה אימייל).  
המוזמן נרשם ב־Aegis עם `invite` + `product=site-secure` → מצטרף לחברה → נוחת ב־`/site-secure/dashboard`.  
קוד `AEGIS-FT-XXX` מוקצה בשרת, לא בהקלדה. האדמין משבץ אתרים ועבודות.

## 5. שלד האפליקציה (אחרי התחברות)

כל מסך מאומת רץ בתוך **AppShell**:

```
┌──────────────┬────────────────────────────────────────┐

│ 260px        │ כותרת עמוד + תת־כותרת                  │
│ lg ומעלה     │ חיפוש (דסקטופ) · פעמון · יצירה מהירה   │
│              │ אווטאר ראשי תיבות                      │
│ לוגו         ├────────────────────────────────────────┤
│ שם חברה      │                                        │
│ תפקיד+plan   │  main  ·  page-content (max 1440px)    │
│              │  fade-in קל כל מעבר עמוד               │
│ סקירה        │                                        │
│ מכירות       │                                        │

             תחתית: 4 קיצורי דרך + «עוד»
             FAB «דווח על בעיה» מעל הניווט
```

### דסקטופ (`lg` = 1024px+)

- סיידבר לבן, גבול שמאלי (RTL: `border-l`), רוחב 260px
- לינק פעיל: רקע **כחול מותג** + טקסט לבן + צל כרטיס
- לינק רגיל: אפור־סלייט, hover משטח אפור בהיר
- קבוצות ניווט נפתחות/נסגרות (Chevron)

### מובייל

- Header עם כפתור תפריט (ריבוע 40×40, פינות 12px)
- מגירה 288px מימין, רקע כהה שקוף מאחור
- Bottom nav קבוע, 5 עמודות, גובה מינימום 60px + safe-area
- קיצורים: **שטח · לוח בקרה · תיקי אתר · קריאות שירות · עוד**
- פריט פעיל: אייקון בתוך ריבוע כחול שקוף + טקסט primary
- `main` מקבל padding-bottom כדי לא להיחסם ע"י הניווט

### Header עליון

| אלמנט | התנהגות |
|--------|---------|
| כותרת | מ־`router.tsx` לפי path (למשל «שטח» / «מצב טכנאי — עבודות היום») |
| חיפוש | רק `lg+`, שדה 288px שמתרחב ל־320px בפוקוס. **UI בלבד — אין חיפוש גלובלי מחובר** |
| פעמון | כפתור עם נקודה כחולה. **UI בלבד — אין רשימת התראות** |
| יצירה מהירה | לפי הרשאות: הצעת מחיר / לקוח / ליד |
| תפריט משתמש | ראשי תיבות על ריבוע כחול, שם+חברה, הגדרות, משתמשים (אם מותר), התנתקות → Aegis בית |

## 6. מפת המסכים — מה יש ומה רואים

כתובות ציבוריות = `/site-secure` + הנתיב.

### 6.1 שטח `/field` — בית הטכנאי

זה מסך היום של השטח (גם `/installations` מפנה לכאן).

**מה מוצג:** רשימת «עבודות היום» = קריאות שירות פתוחות/בטיפול **או** פרויקטים מתוכננים/בביצוע.

כל כרטיס עבודה:

- סוג: קריאה / פרויקט
- כותרת, לקוח, כתובת
- עדיפות (קריאה) או סטטוס (פרויקט)
- SLA אם יש

לחיצה פותחת **Sheet** (מגירה מלמטה במובייל, מודאל ממורכז בדסקטופ):

- ניווט: Google Maps / Waze לפי כתובת
- חיוג ללקוח
- **התחל טיפול** — קריאה `open→in_progress` או פרויקט `planned→in_progress`
- **סיים** — קריאה נסגרת ואז After Action Report; פרויקט פותח Completion Follow-Up (תיק אתר + משימות 60 יום)

### 6.2 לוח בקרה `/dashboard`

ברכה לפי שעה («בוקר טוב {שם}»), שם החברה, תוכנית.

- **Command Ops Strip** — פס תפעולי עם קו גרפיט משמאל
- כרטיסי KPI (לידים, הצעות, פרויקטים, שירות…) עם אייקון כחול עגול
- התראות תפעול: סכנה / אזהרה / מידע (רקע צבעוני + נקודה)
- טבלאות קצרות: הצעות ממתינות, פרויקטים קרובים
- קיצורי דרך לפי `Can`

### 6.3 יומן ומשימות `/calendar`

לא יומן Google. זו רשימת **משימות תפעול** (`company_tasks`):

פולו־אפ, שיחת SLA, ביקור, בקשת ביקורת, מעקב שירות, ביקור 60 יום.

סטטוס: פתוח / בוצע / בוטל. חלק נוצרות אוטומטית מליד/הצעה/פרויקט.

### 6.4 לקוחות `/crm` + לקוח 360 `/crm/:id`

רשימה, חיפוש, יצירה/עריכה/מחיקה.

כרטיס לקוח:

- סוג: פרטי / עסקי
- סטטוס: פעיל / לא פעיל
- טלפון, מייל, כתובת, עיר, ח.פ

360°: אנשי קשר, הערות, פעילות (שיחה/פגישה/מייל). חלק מהפאנלים עדיין «בפיתוח».

### 6.5 לידים `/sales`

משפך:

`חדש → שיחת טלפון → ביקור → אפיון → הצעת מחיר → פולו־אפ → נסגר | אבוד`

מקור: אתר / המלצה / פרסום / טלפון / אחר.  
מדדי משפך בראש העמוד. שינוי סטטוס יכול לפתוח משימת מעקב.

### 6.6 הצעות מחיר — המודול העמוק ביותר

**רשימה** `/quotes` — מספר הצעה, לקוח, סטטוס, סכום, מרווח.

**בונה** `/quotes/new` ו־`/quotes/:id`:

מסך עבודה צפוף (לא «עמוד שיווקי»):

1. כותרת + מספר + סטטוס
2. לקוח / ליד
3. תבנית (דירה, בית פרטי, וילה, משרד, חנות, מחסן) — ממלאת שורות
4. טבלת פריטים: קטלוג / חופשי / שירות / הערה
5. חיפוש מוצר (SKU, מותג)
6. סיכום: עלות ציוד, עבודה, הנחה, מע״מ, מחיר סופי, רווח, מרווח
7. המלצות מוצרים + פאנל AI (UI)
8. פעולות: שמירה (autosave), PDF ממותג, שיתוף WhatsApp, שליחה, אישור

כללי מחיר נאכפים לפי הרשאה (מי רואה עלות רכישה, מי מאשר הנחה).  
חישוב סופי יכול לעבור ל־Edge `recalculate-quote`.  
PDF: HTML RTL → html2canvas → jsPDF. מיתוג מ־`company_settings`.

סטטוסים: טיוטה, נשלחה, אושרה, נדחתה, פגה, בוטלה.

### 6.7 קטלוג `/catalog`

מוצרים לפי קטגוריות אבטחה: מצלמות, NVR/DVR, RISCO, חיישנים, כבלים, PoE, התקנה/חיווט, חוזי שירות, SIM…

כל מוצר: SKU, מותג, עלות, מחיר, זמן התקנה, מלאי (שדה — בלי מודול מלאי מלא).

### 6.8 פרויקטים `/projects`

סטטוס: טיוטה → מתוכנן → בביצוע → מושהה → הושלם | בוטל.

אפשר ליצור מפרויקט מהצעה שאושרה.  
סיום פרויקט: נוצר/מתעדכן **תיק אתר**, נקבעות משימות מעקב.

### 6.9 תיקי אתר `/site-files` — ליבת המוצר

רשימת תיקים עם קוד `AS-S-…`.

**מסך תיק** — טאבים:

| טאב | תוכן |
|-----|------|
| לקוח ואתר | כתובת, סטטוס התקנה, קישור לפורטל ציבורי |
| ציר זמן | אירועי התקנה/שירות |
| Readiness | תתי־מערכות: CCTV, אזעקה, Access, רשת, חשמל, הקלטה… |
| Assessment | בדיקת אתר עם פריטים pass/fail |
| ציוד | סוג, סידורי, סטטוס, שדות רשת |
| אזורים | מפת אזורים באזעקה |
| מסמכים | העלאה ל־bucket פרטי `site-documents` |
| שירות | היסטוריית ביקורים |
| מערכת | הגדרות/סיסמאות מערכת (רגיש) |
| אחריות | תעודות |
| AAR | After Action Report |

פורטל לקוח: `{אתר Aegis}/site/{siteCode}` — מחוץ ל־SPA של SITE SECURE.

במצב Demo **אין** תיקי אתר (דורש Supabase).

סטטוס: פעיל / פג בקרוב / פג / בוטל.

## 7. זרימת העסק המלאה (כפי שקודדה)

```
ליד חדש
  → אפיון / ביקור
  → בונה הצעת מחיר (קטלוג + עבודה + מע״מ)
  → PDF ממותג / WhatsApp
  → אישור לקוח
  → פרויקט מההצעה
  → יום שטח (/field)
  → השלמה
       ├─ תיק אתר AS-S-…
       ├─ ציוד + תמונות + מסמכים
       ├─ תעודת אחריות + מייל ללקוח
       ├─ משימת ביקור 60 יום
       └─ After Action Report
  → קריאות שירות על אותו תיק
  → פורטל לקוח /site/{קוד}
```

זה הלב. השאר (מלאי, חשבוניות, דוחות) עדיין לא בשרשרת הזו.

חסר: חיפוש גלובלי אמיתי, מרכז התראות, dark mode, החלפת שפה בזמן ריצה.

## 9. איך הנתונים זורמים (טכני ל־UX)

```
UI (React 19)
  → TanStack Query (stale 60s)
      → src/lib/*/service.ts
          → supabase-js  →  Postgres + RLS
          → Storage (מסמכי אתר, PDF אחריות, מיתוג)
          → Edge Functions (הזמנה, checkout, מחיר הצעה, מייל אחריות)
```

- Router: TanStack Router, base `/site-secure/`
- מצב מקומי כבד רק בבונה הצעות: **Zustand**
- ולידציה שם: **Zod**
- אם אין מפתחות Supabase או `VITE_FORCE_DEMO=true`: CRM/מכירות/קטלוג/הצעות רצים מ־localStorage. שטח/תיקי אתר/שירות **לא**.

שמירת סשן משותפת עם Aegis. בלי זה — המשתמש «לא מחובר» ב־SITE SECURE גם אם התחבר בפורטל.

## 14. משפט סגירה ל־V2

SITE SECURE היום הוא **מוצר שדה בעברית** עם עיצוב SaaS קר־מקצועי (כחול פלדה, RTL, מובייל־first לשטח) ומודול הצעות/תיק־אתר בשל.  
המעטפת (ניווט, הגדרות, תמחור, פיילוט FT) רחבה יותר מהעומק של מלאי/כספים/דוחות.  
כל שינוי V2 צריך לשמור: RTL, תיק האתר כמקור אמת להתקנה, בונה הצעות עם עלות/רווח, וגישת FT לפי שיבוץ — לא לפי «הסתרה ב־UI».
